# VINMERGE Visual Layer — Integration Specification

## Status

The visual architecture and deterministic ingestion boundary are implemented on this branch. CI now validates the ingestion contract, generated sidecar structure and ingestion unit tests.

The existing master catalogue remains unchanged because it is stored as a Git LFS object. The visual layer is therefore integrated through a canonical-record sidecar until the catalogue is regenerated by the development pipeline.

## Canonical integration

The master catalogue remains the authoritative identifier source. The visual layer is keyed by `canonical_record_id` and may be materialized into API responses as the `visual` object.

```text
canonical vehicle/component/part record
    + visual layer by canonical_record_id
    = VINMERGE enriched record
```

Do not copy vehicle definitions into the visual index.

## Ingestion boundary

`visual/ingestion/ingest_visual_assets.py` accepts a versioned ingestion manifest, validates the required identifiers and controlled vocabularies, hashes local image files with SHA-256 when present, and produces one visual sidecar record per canonical identifier.

The ingestion layer does **not** establish VIN identity, chassis/frame identity, OEM fitment, interchangeability or supplier stock truth.

## Empty-state behavior

Every supported record may safely return an empty visual layer:

```json
"visual": {
  "visual_layer_version": "1.0",
  "visual_assets": [],
  "ai_visual_metadata": {
    "enabled": true,
    "visual_embedding_ref": null,
    "detected_part_labels": [],
    "detected_attributes": [],
    "duplicate_group_id": null,
    "normalization_status": "not_processed",
    "fitment_signal": "none",
    "human_review_required": false
  }
}
```

## Asset priority in the product UI

1. Exploded/technical illustration for component location and navigation.
2. Actual product image for purchase confirmation.
3. Installation/context image when useful.
4. Packaging image for part-number/brand verification.
5. Vehicle-context image for orientation.

The UI should gracefully fall back when a layer is unavailable; no record should be rejected solely because an image is missing.

## AI controls

AI visual output is supporting evidence. It can propose labels, attributes, duplicates, visual similarity and mismatch flags, but it must not silently convert those signals into authoritative fitment.

## Dealer onboarding

Dealer upload should capture at minimum:

- canonical record/part reference;
- asset type and role;
- source type and source name;
- licence/permission status;
- original image reference;
- storage reference when available;
- image hash when processed;
- review status.

The platform can then run normalization, AI enrichment and duplicate/mismatch checks before publishing the image.

## CI contract

The workflow `.github/workflows/visual-ingestion-ci.yml` checks:

1. Python compilation;
2. ingestion unit tests;
3. ingestion-manifest schema validity;
4. sidecar generation;
5. generated sidecar schema validity.

This closes the previous structural gap where the visual contract existed without an executable ingestion path or automated validation.
